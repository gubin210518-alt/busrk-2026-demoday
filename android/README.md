# 부스럭 예냉박스 안드로이드 앱

예냉박스(ESP32)를 **블루투스(BLE)로 원격 확인**하는 앱이에요. 인터넷이나 공유기 없이 밭에서 바로 동작하고, 거리는 약 10m예요.

> 이 앱은 블루투스판 펌웨어 `firmware/precool_ai_ble/precool_ai_ble.ino`와 함께 써요.
> 기존 `precool_ai.ino`, `precool_ai_demo.ino`에는 블루투스 기능이 없어요.

## 1. 앱에 들어 있는 것

| 탭 | 기능 |
|---|---|
| 현황 | 박스 찾기·연결, 신호등 상태(식히는 중/완료/늦을 위험/늦음/센서 확인), 식품칸·냉기실 온도, 목표까지 남은 시간과 **도착 예상 시각**, 제한 시간 진행 막대, 온도 그래프(목표선·제한 시간선·뚜껑 열린 구간), 새 딸기 시작(PIN), 최근 10분 다시 받기 |
| 기록 | 회차별 CSV 기록(2초 간격) 목록, **실험 조건 메모**(바깥 온도·딸기 양·아이스팩), 보내기(공유), 삭제 |
| 설정 | 알림 켜기/끄기 6종, 연결된 박스 정보(목표 온도, 제한 시간, 시연 모드, AI 모델이 시뮬레이션인지), 보안·개인정보 안내 |

- **화면을 꺼도 계속 확인해요.** 연결하면 상단에 "연결 중" 알림이 생기고, 그동안 휴대폰 주머니에 넣어 둬도 상태를 받아요.
- **알림**: 늦을 위험, 제한 시간 지남, 예냉 완료, 뚜껑 30초 넘게 열림, 센서 오류, 연결 끊김.
- **자동 다시 연결**: 거리를 벗어났다가 다시 가까이 가면 자동으로 다시 연결해요.
- **연결 전 기록 채우기**: 연결하면 박스에 남아 있는 최근 10분 기록을 받아 그래프 앞부분을 채워요.
- **AI 재학습 연결**: 기록 CSV의 앞 5칸이 AI 시뮬레이터 형식과 같아서, PC로 보내 "실험 기록 → CSV 불러오기"로 바로 학습에 쓸 수 있어요.

## 2. Android Studio에서 열기

1. Android Studio를 실행하고 **Open**을 눌러 이 `android` 폴더를 고릅니다. (저장소 전체가 아니라 `android` 폴더)
2. 처음 열면 Gradle 동기화(Sync)가 자동으로 돌아요. 인터넷이 필요하고 몇 분 걸려요.
   - 필요한 SDK(Android 16, API 36)가 없다고 나오면 안내에 따라 설치해요.
   - "AGP Upgrade Assistant"가 업그레이드를 권하면 **나중에** 해도 돼요. 이 프로젝트는 AGP 8.13 / Gradle 8.14.3 / Kotlin 2.2.20 / Compose BOM 2025.08.00 기준이에요.
3. 휴대폰을 USB로 연결하고 **개발자 옵션 → USB 디버깅**을 켭니다.
4. 위쪽 ▶(Run) 버튼을 누르면 휴대폰에 설치돼요.

> ⚠️ 이 프로젝트는 만든 환경에서 안드로이드 빌드 도구를 받을 수 없어서 **실제 빌드는 아직 못 해 봤어요.**
> 문법 검사와 블루투스 데이터 해석 검사는 통과했어요. 빌드 오류가 나면 오류 문구를 그대로 알려 주세요.

## 3. 처음 연결하기

1. 박스에 `precool_ai_ble.ino`를 업로드합니다. (펌웨어 맨 위 안내대로 Partition Scheme을 **Huge APP**으로 바꾸고, `BLE_PIN`을 6자리로 정하기)
2. 앱 → 현황 → **예냉박스 찾기** → 권한 허용(주변 기기, 알림) → 목록의 `BUSRK-XXXX`를 누릅니다.
3. 다음부터는 **"지난 박스 다시 연결"** 버튼으로 바로 연결돼요.

## 4. 폴더 구조

```

    MainActivity.kt          앱 시작

    ble/BoxProtocol.kt       펌웨어와 약속한 데이터 형식 (UUID, 바이트 해석)

    ble/BoxScanner.kt        주변 박스 찾기
    data/BoxRepository.kt    화면과 서비스가 같이 보는 상태, 휴대폰 설정 키
    data/RunStore.kt         회차별 CSV 저장·읽기

```

## 5. 블루투스 통신 형식 (펌웨어 ↔ 앱)

서비스 UUID `b5a10001-7c3e-4f2a-9d6b-1e8c0f4a2b70`. 숫자는 모두 작은 끝 순서(little-endian)예요.

| 특성 | UUID 끝 | 방향 | 내용 |
|---|---|---|---|
| 상태 | `…0002` | 박스→앱, 2초마다 알림 | 20바이트 (아래 표) |
| 설정 | `…0003` | 앱이 읽기 | 목표×100(int16), 제한분×10(uint16), 시연, 시뮬레이션 모델, 원격 명령 가능, 형식 버전, 기록 간격 초(uint16) |
| 명령 | `…0004` | 앱→박스 쓰기, 결과는 알림 | `h` 최근 10분 기록 / `r`+PIN6자리 새 딸기. 결과: `OK h`, `EMPTY`, `OK r`, `PIN`, `LOCK`, `NOPIN`, `?` |
| 기록 | `…0005` | 박스→앱 알림 | 14바이트씩: 번호, 전체 수, 시각 ms(uint32), 식품칸×100, 냉기실×100, 깨끗함(팬 켜짐·뚜껑 닫힘) |

상태 20바이트:

| 위치 | 크기 | 내용 |
|---|---|---|
| 0 | uint16 | 순번 |
| 2 | uint32 | 경과 초 (수확 후 시간) |
| 6 | int16 | 식품칸 ℃×100 (−32768 = 못 읽음) |
| 8 | int16 | 냉기실 ℃×100 |
| 10 | uint8 | 상태 0 식히는 중 / 1 완료 / 2 늦을 위험 / 3 늦음 / 4 센서 확인 |
| 11 | uint8 | 비트: 1 뚜껑 열림, 2 팬, 4 시연, 8 AI 유지값, 16 완료 유지, 32 뚜껑 30초 경고 |
| 12 | int16 | 판단에 쓴 남은 분×10 (−10 모름, −20 못 닿음) |
| 14 | uint8 | 방법 글자 `A` AI, `N` 뉴턴, `L` 직선, `-` 없음 |
| 15 | uint8 | 목표 도달 분 (255 = 아직) |
| 16 | int16 | 뉴턴 남은 분×10 |
| 18 | int16 | AI 남은 분×10 |

20바이트로 맞춘 이유: 블루투스 기본 한 번에 보낼 수 있는 양이 20바이트라, 휴대폰 기종에 상관없이 잘리지 않아요.

## 6. 보안과 개인정보

- 인터넷 권한이 없어요. 기록은 휴대폰 안(`앱 전용 저장공간/runs`)에만 있고, "보내기"를 누를 때만 밖으로 나가요. 앱 백업(`allowBackup`)도 꺼 두었어요.
- 개인정보·위치를 모으지 않아요. 안드로이드 11 이하의 위치 권한은 블루투스 검색 때문에만 필요해요. 12 이상은 "위치에 쓰지 않음"으로 표시해요.
- 블루투스 내용은 암호화하지 않아요. 근처 사람이 온도 값을 볼 수 있어요. (개인정보가 아니라서 이 단계에서는 감수)
- 박스를 바꾸는 명령은 PIN 6자리가 필요하고, 5번 틀리면 1분 잠겨요. PIN이 `000000`이면 원격 명령 자체가 꺼져요.
- PIN은 블루투스로 그대로 가기 때문에, 전문 장비가 있으면 엿볼 수 있어요. 더 강하게 하려면 블루투스 페어링(암호화)을 다음 단계로 넣어야 해요.
- 기록 삭제(`x`) 같은 명령은 블루투스로 받지 않아요.
