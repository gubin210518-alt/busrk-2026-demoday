# 부스럭 예냉박스 AI — 기술 설명서

TEAM 부스럭 (신정고 매니악코더) · 식품의 골든타임을 지키는 예냉박스

- AI 시뮬레이터(PC 프로그램): https://busrk-ai-studio.vercel.app
- 펌웨어: `precool_ai.ino`(실사용, 목표 1℃·60분), `precool_ai_demo.ino`(시연, 목표 15℃·10분)

---

## 1. 이 AI가 푸는 문제

수확한 딸기는 1시간 안에 예냉하는 것이 중요합니다. 박스는 지금 온도만 보여 주는 것이 아니라 **"이대로 식히면 목표 온도(1℃)까지 몇 분 남았는지"**를 예측하고, 제한 시간(60분) 안에 될지 판단해 신호등으로 알려야 합니다.

뉴턴 냉각 법칙만으로 예측하면 다음을 놓칩니다.

| 계산식이 놓치는 것 | 이유 |
|---|---|
| 아이스팩이 녹으면서 냉기실이 점점 따뜻해짐 | 뉴턴 식은 냉기 온도를 일정하다고 가정 |
| 딸기 덩어리가 공기보다 늦게 식음 | 센서는 식품칸 공기 온도만 잼. 처음엔 공기가 빨리 식다가 딸기가 열을 내놓으며 느려짐 |
| 박스마다 단열·팬 세기·딸기 양이 다름 | 식 하나에 고정된 계수로는 표현이 어려움 |

그래서 **실험 기록에서 이 박스의 냉각 패턴을 배우는 학습 모델(AI)**을 만들었습니다.

## 2. 접목된 기술 한눈에 보기

| 분야 | 기술 | 어디에 쓰였나 |
|---|---|---|
| 머신러닝 | **선형 회귀 + 릿지 규제(L2)** | 2분 뒤 온도 변화 예측 모델 |
| 머신러닝 | **특징 표준화(Z-score)** | 입력 단위(℃, ℃/분)를 맞춰 학습 안정화 |
| 시계열 예측 | **자기회귀 반복 예측(rollout)** | 2분 예측을 반복해 목표 도달 시각 계산 |
| 물리 모델 | **뉴턴 냉각 법칙 + 로그 선형 회귀** | 비교 기준, AI가 계산 못 할 때의 대체 예측 |
| 수치 계산 | **가우스 소거법(부분 피벗)** | 정규방정식을 풀어 가중치 구하기 |
| 데이터 처리 | **선형 보간 리샘플링** | 간격이 제각각인 기록을 10초 격자로 정리 |
| 시뮬레이션 | **3-노드 열 모델 + 몬테카를로 무작위 계수** | 가상 실험 데이터 생성(사전 학습·시연용) |
| 임베디드 AI | **온디바이스 추론(TinyML 방식)** | 학습한 숫자 18개를 ESP32에 넣어 보드에서 직접 예측 |
| 웹 | **Web Serial API** | 브라우저가 USB로 ESP32와 직접 통신 |
| 평가 | **실험 단위 분리 검증 + MAE** | 학습에 안 쓴 실험으로 오차 비교 |

## 3. 동작 흐름 (인지 → 판단 → 행동)

```
[DS18B20 x2]  식품칸 온도 b, 냉기실 온도 c   (10초마다 기록)
      │
      ▼
[특징 만들기]  x = [ b−c,  c,  (b−b₂분전)/2,  (c−c₂분전)/2 ]
      │
      ▼
[학습 모델]    Δb̂, Δĉ = 2분 뒤 온도 변화 예측
      │   └─ 2분씩 반복(최대 180분) → 목표 1℃에 닿는 시각
      ▼
[판단]         지금 경과 + 예측 남은 시간 > 60분 ?  → 빨강+부저
               아니면 노랑, 목표 도달하면 초록
      │
      ▼
[행동]         댐퍼·팬 제어, OLED "ETA 12m AI", 기록 저장, PC로 전송
```

## 4. 모델 설계 상세

### 4-1. 입력(특징) 4개

| 번호 | 특징 | 의미 |
|---|---|---|
| x₁ | b − c | 식품칸과 냉기실의 온도 차. 뉴턴 법칙에서 식는 속도를 정하는 핵심 값 |
| x₂ | c | 냉기 자체의 온도. 아이스팩 상태를 반영 |
| x₃ | (b(t) − b(t−2분)) / 2 | 식품칸이 최근 2분 동안 식은 속도(℃/분). 딸기 덩어리의 열 상태가 여기에 드러남 |
| x₄ | (c(t) − c(t−2분)) / 2 | 냉기실 온도가 변하는 속도. 아이스팩이 녹는 정도 |

x₃이 중요한 이유: 센서가 재지 못하는 딸기 속 온도(숨은 상태)가 공기 온도의 기울기에 흔적을 남깁니다. 열 전달식을 정리하면 딸기 온도 M은 `공기 온도 + (공기 기울기 + 냉각 항)/계수` 꼴로 표현되어, 기울기를 넣으면 선형 모델로도 숨은 상태를 간접적으로 반영할 수 있습니다.

### 4-2. 출력 2개

- Δb = b(t+2분) − b(t) : 2분 뒤 식품칸 온도 변화
- Δc = c(t+2분) − c(t) : 2분 뒤 냉기실 온도 변화

"남은 시간"을 바로 배우지 않고 "2분 뒤 변화"를 배우는 이유는 다음과 같습니다.

1. 목표 온도에 끝까지 닿지 못한 실험도 학습에 쓸 수 있습니다(모든 시점에 정답이 있음).
2. 목표 온도를 바꿔도 다시 학습할 필요가 없습니다(1℃든 15℃든 같은 모델).
3. 예측 경로 전체를 그래프로 보여 줄 수 있습니다.

### 4-3. 학습: 표준화 + 릿지 회귀

1. 각 특징을 평균 μ, 표준편차 σ로 표준화: `z = (x − μ) / σ`
2. 예측식: `Δb̂ = w₀ + w₁z₁ + w₂z₂ + w₃z₃ + w₄z₄` (Δc도 같은 꼴, 가중치만 다름)
3. 가중치는 다음 손실을 최소로 하는 값입니다.

```
L(w) = Σ (Δb̂ − Δb)²  +  λ · (w₁² + w₂² + w₃² + w₄²)
```

   λ(과적합 방지 값)는 가중치가 지나치게 커지는 것을 막습니다. 기록이 적을 때 모델이 우연한 잡음까지 외워 버리는 것(과적합)을 줄입니다. 절편 w₀에는 규제를 걸지 않습니다. 기본값 λ = 1.

4. 해는 정규방정식 `(ZᵀZ + λI) w = ZᵀΔb`를 **가우스 소거법(부분 피벗)**으로 풀어 한 번에 구합니다. 반복 학습(경사하강법)이 필요 없어 브라우저에서 수만 개 표본도 바로 학습됩니다.

학습 표본은 팬이 켜져 있고 뚜껑이 닫힌 구간만 씁니다. 표본 하나에 앞뒤 2분(총 4분)이 깨끗해야 합니다.

### 4-4. 예측: 2분씩 반복(rollout)

```
목표 도달까지 남은 시간(b, c, 기울기들):
  t = 0
  최대 90번(180분) 반복:
     Δb̂, Δĉ = 모델(b, c, 기울기)
     b' = b + Δb̂,  c' = c + Δĉ
     b' ≤ 목표  →  t + 2 × (b − 목표)/(b − b')  반환   (구간 안 선형 보간)
     Δb̂ > −0.005 (더 이상 안 식음) → "못 닿음" 반환
     기울기 = Δb̂/2, Δĉ/2 로 갱신,  t += 2
  → "못 닿음"
```

예측한 값을 다음 입력으로 다시 넣는 **자기회귀(autoregressive) 방식**입니다. 이 경로가 시뮬레이터 그래프의 보라색 점선입니다.

### 4-5. 비교 기준: 뉴턴 냉각 법칙

```
T(t) = T냉기 + (T처음 − T냉기) · e^(−k t)
```

- 최근 10분 기록으로 `ln(b − 냉기평균)`을 시간에 대해 직선 회귀하면 기울기가 −k입니다.
- 남은 시간 = `ln((b − T냉기)/(목표 − T냉기)) / k`
- 냉기실 센서를 못 읽으면 식품칸 온도의 직선 추세로 대신 계산합니다.

박스는 처음 2분(기울기를 아직 못 구함)과 냉기실 센서 오류 때 이 값으로 판단합니다.

## 5. 구현 상세

### 5-1. ESP32 펌웨어 (`precool_ai.ino`)

- 학습 결과는 숫자 18개뿐입니다(평균 4, 표준편차 4, 가중치 5×2). 코드 안 "학습 모델 (model.h)" 블록에 `static const float` 배열로 들어갑니다. 메모리 약 72바이트.
- `aiStep()` 2분 뒤 변화 계산, `aiEta()` 반복 예측(최대 90회). 곱셈 수십 번이라 ESP32에서 1ms도 안 걸립니다.
- 10초마다 기록하는 원형 버퍼(최근 10분, 60칸)에서 `histAt()`이 2분 전 값을 앞뒤 기록으로 **보간**해 꺼냅니다. 기록 간격이 바뀌어도(시연 모드 5초) 시간 기준으로 동작합니다.
- 판단 순서: AI 예측 → (없으면) 뉴턴 → (없으면) 직선 추세.
- 10초마다 PC로 `D,분,식품칸,냉기실,뚜껑,팬,상태,뉴턴ETA,AI_ETA` 한 줄을 보내고, 시작할 때 `CFG,목표,제한,시연여부`를 보냅니다.
- 시리얼 명령: `r` 새 딸기, `m` 모델 정보, `d` 기록 출력, `x` 기록 삭제, `a` 센서 주소.

### 5-2. AI 시뮬레이터 (PC 프로그램, HTML 하나)

설치 없이 크롬/엣지에서 동작하고, 외부 라이브러리 없이 순수 JavaScript로 만들었습니다.

| 탭 | 하는 일 |
|---|---|
| 실시간 | Web Serial로 ESP32 데이터 수신, 온도 그래프·AI 예측 경로·신호등 표시. 하드웨어가 없으면 가상 상자 시뮬레이션 |
| 실험 기록 | 연결 중 자동 기록(시간이 0으로 돌아가면 새 실험), log.csv 불러오기, 가상 실험 생성. 브라우저에 저장 |
| AI 학습 | 체크한 실험으로 학습 → 직선/뉴턴/AI 오차 비교 → 성공 기준 4 판정 |
| 펌웨어로 보내기 | 학습 결과를 model.h 형식으로 내보내기 |

리샘플링: 기록 간격(10초, 30초 등)이 달라도 10초 격자로 **선형 보간**해서 학습·평가를 펌웨어와 같은 조건으로 맞춥니다.

### 5-3. 가상 상자 시뮬레이터 (사전 학습·시연용)

열이 오가는 덩어리 셋으로 박스를 나타낸 미분방정식을 1초 간격으로 풉니다(오일러 적분).

```
dA/dt = −k팬(A − C) − k접촉(A − M) − k누설(A − 바깥)     A: 식품칸 공기(측정)
dM/dt = −k딸기(M − A)                                     M: 딸기 덩어리(측정 안 됨)
dC/dt = −k얼음(C − T얼음) + 0.35·k팬(A − C) − 누설         C: 냉기실(측정)
```

- 아이스팩은 녹을 열량(잠열)이 남아 있는 동안 영하를 유지하다가, 다 녹으면 따뜻해집니다.
- 실험마다 바깥 온도, 팬 세기, 딸기 양, 아이스팩 양 등 계수를 정해진 범위에서 **무작위로** 뽑습니다(몬테카를로). 센서 잡음(±0.04℃)과 DS18B20 해상도(0.0625℃)도 흉내 냅니다.
- **주의: 계수는 그럴듯한 범위로 가정한 값이고, 실제 상자에서 잰 값이 아닙니다.**

### 5-4. 평가 방법 (성공 기준 4)

- 실험을 **실험 단위로** 나눕니다(5개 중 1개는 시험용). 같은 실험의 앞뒤 구간이 학습과 시험에 섞이지 않게 해서 성능이 부풀려지지 않게 합니다.
- 시험 실험에서 목표에 실제로 닿은 시각을 정답으로 하고, 닿기 전 30초마다 세 방법의 "남은 시간" 예측 오차를 평균(MAE, 분)합니다.
- "못 닿음"으로 잘못 예측하면 180분 오차로 계산합니다.
- 판정: AI 오차 < 뉴턴 오차 그리고 AI 오차 < 직선 오차.

## 7. 한계와 다음 단계

- **실측 데이터로 다시 학습해야 합니다.** 지금 들어 있는 모델은 시뮬레이션으로 학습 구조를 검증한 단계입니다. 실험을 반복해 기록을 모으고, 실측 기록만 체크해서 다시 학습합니다.
- **실제 보드에서 끝까지 돌려 본 기록이 아직 없습니다.** 컴파일과 PC 쪽 동일성 검증까지 했습니다.
- **딸기 속 온도는 재지 않습니다.** 식품칸 공기 온도 기준입니다. 판매하지 않을 샘플 딸기에 탐침을 꽂아 과육 온도를 함께 기록하면, 과육 온도를 추정하는 모델로 넓힐 수 있습니다.
- **선형 모델의 한계:** 칸막이 단열(뽁뽁이), 댐퍼 각도, 딸기 양이 크게 바뀌면 다시 학습이 필요합니다. 데이터가 충분히 쌓이면 작은 신경망(MLP)과 비교해 볼 수 있습니다.
- **품질 판정은 하지 않습니다.** 예측은 참고 표시이고, 출하 판단은 농가가 합니다.
