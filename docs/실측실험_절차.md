# 실측 실험 절차 — AI 재학습과 성공 기준 판정용

TEAM 부스럭 · 예냉박스. 기준 시점 2026-11-12.

지금 박스의 AI는 **가상 실험으로만** 학습했어요. 이 문서는 실제 상자로 기록을 모으고, 그 기록으로 AI를 다시 학습하고, 성공 기준 5개를 판정하는 순서를 정한 거예요.

---

## 1. 몇 번 해야 하나요?

가상 실험으로 "실험 수에 따라 AI가 계산식을 이기는지"를 미리 확인했어요. (실험 1개 = 60분, 실험을 하나씩 빼고 학습해서 뺀 실험으로 시험, 서로 다른 가상 실험 묶음 3세트)

| 실험 수 | AI 오차 (분) | 직선 추세 | 뉴턴 계산식 | AI가 가장 작았나 |
|---|---|---|---|---|
| 3 | 19.6 / 1.1 / 평가 불가 | 14.4 / 9.9 / - | 56.9 / 66.4 / - | 1/2세트 |
| 5 | 3.8 / 2.1 / 평가 불가 | 15.5 / 9.7 / - | 68.6 / 66.4 / - | 2/2세트 |
| 8 | 3.2 / 3.7 / 23.4 | 13.9 / 9.6 / 9.8 | 63.3 / 62.7 / 94.4 | 2/3세트 |
| 10 | 3.6 / 4.3 / 23.3 | 13.0 / 10.1 / 9.8 | 61.3 / 49.7 / 94.4 | 2/3세트 |
| 15 | 3.8 / 4.7 / 11.2 | 12.1 / 12.3 / 12.3 | 46.3 / 50.1 / 48.5 | 3/3세트 |
| 20 | 4.4 / 4.7 / 8.3 | 12.1 / 12.6 / 13.3 | 49.4 / 58.7 / 41.8 | 3/3세트 |

"평가 불가"는 60분 안에 1℃에 닿은 실험이 없어서 비교할 수 없었다는 뜻이에요.

**결론: 최소 10회, 권장 15회 이상.** 10회 미만이면 실험 조합에 따라 AI가 오히려 계산식보다 나빠질 수 있어요.

> 가상 실험 기준이라 실제와 다를 수 있어요. 실제 기록이 쌓이면 시뮬레이터 "AI 학습" 탭 결과로 다시 판단해요.

## 2. 준비물과 사전 점검

| 준비물 | 용도 |
|---|---|
| 예냉박스 (펌웨어 `precool_ai_ble.ino`, **DEMO_MODE = false**) | 실험 |
| 안드로이드 휴대폰 + 앱 "부스럭 예냉박스" | 기록(2초 간격), 메모 |
| (선택) 노트북 + AI 시뮬레이터 | USB로 기록 (10초 간격) |
| 탐침형 디지털 온도계 | 센서 보정, 딸기 과육 온도 |
| 아이스팩 여러 개 | 회차마다 꽁꽁 언 것 사용 |
| 저울 | 딸기 양 |
| 판매하지 않을 샘플 딸기 | 과육 온도 재기 (탐침을 꽂으니까) |

**사전 점검 (첫날 한 번)**
1. `parts_check.ino`로 부품이 모두 동작하는지 확인해요.
2. **센서 보정 (성공 기준 4)**: 얼음물(0℃)과 실온 물, 두 곳에서 DS18B20 2개와 탐침 온도계를 같이 넣고 3분 뒤 값을 비교해요. 센서마다 차이가 ±1℃ 안이면 합격이에요. 기록지에 적어요.
3. 센서 주소를 확인해요(시리얼 `a`). 식품칸·냉기실 센서가 바뀌지 않았는지 손으로 잡아 데워 보며 확인해요.

## 3. 회차마다 바꿀 조건

AI가 여러 상황을 배우려면 조건을 **골고루** 바꿔야 해요. 특히 **1시간 안에 못 식는 회차도 일부러 넣어야** 성공 기준 2(미리 경고)를 판정할 수 있어요.

| 조건 | 값 예시 |
|---|---|
| 바깥 온도 | 실내 그늘 / 실외 그늘 / 햇빛 |
| 딸기 양 | 250g / 500g / 1kg |
| 아이스팩 | 1개 / 2개 / 3개 |
| 딸기 처음 온도 | 수확 직후(실온) 그대로 |

15회 예시: 아이스팩 2개·딸기 500g을 기본으로 5회, 나머지 10회는 한 가지씩 바꿔요. 그중 3~5회는 "아이스팩 1개 + 딸기 1kg + 햇빛"처럼 늦을 만한 조건으로 해요.

---

## 4. 한 회차 순서

1. 아이스팩을 12시간 이상 얼려요.
2. 탐침 온도계로 샘플 딸기 과육 온도를 재서 적어요.
3. 아이스팩을 냉기실에, 딸기를 식품칸에 넣고 뚜껑을 닫아요.
4. 박스 전원을 켜거나, 앱에서 **새 딸기 시작**(PIN)을 눌러 0분부터 시작해요.
5. 앱이 연결된 상태로 **최소 60분, 가능하면 90분** 기록해요. 1시간 안에 못 닿아도 계속 기록해야 "언제 닿는지"를 AI가 배워요.
6. 중간에 뚜껑은 되도록 열지 않아요. 열었다면 시각을 메모해요.
7. 끝나면 샘플 딸기 과육 온도를 다시 재요.
8. 앱 → 기록 → 해당 회차 **조건 메모**에 적어요. 예: `바깥 24℃ 그늘, 딸기 500g, 아이스팩 2개, 과육 23.5→3.1℃, 뚜껑 1회(20분)`

**기록 받는 길 (하나만 있어도 돼요)**
- 앱: 기록 → 보내기 → PC로 CSV 전송 (2초 간격)
- AI 시뮬레이터: USB로 연결해 두면 "실험 기록"에 자동 저장 (10초 간격)
- 보드: 시리얼 `d` 명령으로 `log.csv` 출력 (30초 간격)

## 6. 성공 기준 판정 방법 (구체화)

| 기준 | 판정 방법 |
|---|---|
| 1. 냉각 성능 | 회차마다 목표 1℃ 도달 여부와 걸린 분을 적어요. 전체 회차의 도달 비율과 평균 걸린 시간을 발표해요. |
| 2. 미리 경고 | **60분 안에 못 닿은 회차**만 봐요. 그중 **45분이 되기 전에** "늦을 위험"이 한 번이라도 뜬 회차의 비율이 80% 이상이면 통과. (10회 중 8회) |
| 3. 헛경고 | **60분 안에 닿은 회차**만 봐요. 그중 "늦을 위험"이 **1분 넘게 이어진** 회차의 비율이 20% 이하면 통과. (10회 중 2회) |
| 4. 측정 정확도 | 2장의 센서 보정에서 두 센서 모두 기준 온도계와 ±1℃ 안이면 통과. |
| 5. AI 예측 | 시뮬레이터 "AI 학습" 탭에서 **실측 기록만 체크**하고 학습해요. AI 오차가 직선 추세와 뉴턴 계산식보다 모두 작으면 1번 확인. 실험이 10회, 15회, 20회 모였을 때 **3번** 확인해서 모두 통과해야 최종 통과. |

- 2번의 "45분"과 3번의 "1분"은 이 문서에서 처음 정한 값이에요. 팀에서 다른 값으로 정해도 되지만, **실험 전에** 정하고 바꾸지 않아야 공정해요.
- 2·3번은 두 종류 회차가 각각 5회 이상 있어야 비율이 의미가 있어요.
- 5번 평가는 목표에 실제로 닿은 회차만 쓸 수 있어요. 1℃에 닿은 회차가 적으면 시뮬레이터의 "평가 목표 온도"를 5℃로 바꿔 함께 보고, 발표 때 어떤 온도로 평가했는지 밝혀요.
- 실험이 5회보다 적으면 시뮬레이터가 자동으로 "한 개씩 빼기 검증"을 해요. 학습한 실험으로 시험하지 않아서 결과가 부풀려지지 않아요.

## 7. AI 다시 학습하고 박스에 넣기

1. AI 시뮬레이터 → 실험 기록 → **CSV 불러오기**로 앱에서 보낸 파일들을 넣어요.
2. **가상 실험은 모두 체크 해제**(또는 "가상 실험 지우기")하고 실측만 남겨요.
3. AI 학습 → 학습하기. 과적합 방지 λ는 기본값 1을 써요. (칸을 비우면 자동으로 1)
4. 오차 비교에서 AI가 가장 작은지 확인 → "이 모델을 사용하기".
5. 펌웨어로 보내기 → model.h 복사 → `precool_ai_ble.ino`의 "학습 모델 (model.h)" 블록(MODEL_READY ~ MODEL_WC)을 바꿔 넣고 업로드해요.
6. 앱 → 설정 → 연결된 박스 정보에서 "AI 모델: 실측 기록으로 학습"으로 바뀌었는지 확인해요.
7. 새 모델로 3회 이상 더 실험해서, 실제로 예측이 맞는지 확인해요. (이 3회는 학습에 넣지 않고 시험용으로만 써요)
