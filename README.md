## 3. 하드웨어

### 3-1. 상자 구조
- 스티로폼 상자를 **폼보드 칸막이**로 나눠서 **냉기실**(아이스팩)과 **식품칸**(딸기)으로 써요.
- 칸막이에서 **냉기실 쪽 면(식품칸과 맞닿는 면)은 뽁뽁이(에어캡)로 단열**해요. 창 부분은 뚫려 있어요.
- 칸막이 창에는 **SG90 서보로 여닫는 폼보드 댐퍼**와 **5V 쿨링팬**을 달아요. 팬은 냉기실의 찬 공기를 식품칸으로 보내요.
- **DS18B20 온도센서 2개**를 식품칸 공기와 냉기실 공기에 하나씩 둬요. 딸기에 직접 닿게 하지 않아요.
- ESP32와 표시부(OLED·신호등 LED·부저)는 상자 옆면 전장 케이스에, 리드스위치와 자석은 뚜껑에 달아요.
- 3D 부착도(three.js)는 홈페이지 `index.html`/`app.js`에 있어요. 상자 크기는 40×28×26cm로 가정했어요.

### 3-2. 부품

| 부품 | 역할 |
|---|---|
| ESP32 WROOM 보드 (HW-394, USB-C, 30핀) | 센서 읽기, 예측, 팬·댐퍼 제어, 기록 |
| DS18B20 방수 온도센서 ×2 | 식품칸·냉기실 공기 온도 |
| SG90 서보 + 폼보드 댐퍼 | 냉기실 창 여닫기 |
| 5V 쿨링팬 + MOSFET 모듈 (+ 1N5819 다이오드) | 찬 공기를 식품칸으로 순환 |
| OLED 0.96" (SSD1306, I2C 0x3C) · 신호등 LED 모듈 · 액티브 부저 모듈 | 온도, 남은 시간, 경고 표시 |
| 리드스위치 모듈 + 자석 | 뚜껑 열림 감지 |
| 스티로폼 상자 · 아이스팩 | 본체와 냉기 공급 |
| 폼보드 칸막이 · 뽁뽁이(에어캡) | 냉기실과 식품칸 분리, 맞닿는 면 단열 |
| 탐침형 디지털 온도계 | 센서 보정, ±1℃ 검증 |

재료 예산은 10만 원이고, 신청 목록 합계는 배송비를 빼고 70,300원이에요.

### 3-3. 핀 연결 (보드에 인쇄된 이름)

| 핀 | 연결 |
|---|---|
| D4 | DS18B20 ×2 DATA (4.7kΩ로 3.3V에 풀업, 저항은 1개) |
| D18 | 서보 신호 (서보 전원 5V) |
| D19 | MOSFET 모듈 PWM (팬 전원 5V) |
| D21 / D22 | OLED SDA / SCL |
| D27 | 리드스위치 DO (3.3V 전원) |
| D26 / D33 / D32 | LED 빨강 / 노랑 / 초록 |
| D25 | 부저 I/O |

- 전원은 3V3를 가운데 왼쪽 + 줄(3.3V 줄)로, VIN을 가운데 오른쪽 + 줄(5V 줄)로 옮겨 써요.
- 배선 순서는 홈페이지 배선도 단계별 버튼에 나와 있어요.
- MOSFET 모듈은 판매 페이지 기준 최소 6V라서, 5V에서는 팬이 약하게 돌 수 있어요.

## 4. 펌웨어 동작 (`firmware/precool_ai/precool_ai.ino`)

**설정값**

| 설정 | 값 |
|---|---|
| 목표 온도 `TARGET_C` | 1.0℃ (시연 15℃) |
| 제한 시간 `DEADLINE_MIN` | 60분 (시연 10분) |
| 다시 식히기 시작 | 목표 + 0.5℃ 넘을 때 |
| 얼림 방지 | 식품칸 0℃ 아래면 팬 정지 |
| 예측용 기록·PC 전송 간격 `HIST_MS` | 10초 (시연 5초) |
| 보드 기록 `log.csv` (LittleFS) | 30초마다 |
| 뚜껑 열림 부저 | 30초 넘게 열려 있으면 |
| 댐퍼 각도 | 닫힘 0°, 열림 90° |
| 리드스위치·부저 활성 레벨 | LOW (반대 모듈이면 HIGH로 변경) |
| 센서 주소 | 비워 두면 찾은 순서대로 0번=식품칸, 1번=냉기실 |

**동작 규칙**
- 전원을 켠 순간을 "수확 후 0분"으로 봐요.
- 넣자마자 댐퍼를 열고 팬을 켜요.
- 뚜껑이 열리면 팬을 멈춰요.
- 센서 오류일 때는 "측정 불가"로 표시하고 팬을 멈춰요.

**표시**

| 상태 | 신호등 | 부저 |
|---|---|---|
| 목표 도달 | 초록 | 없음 |
| 식히는 중, 1시간 안에 될 것 같음 | 노랑 | 없음 |
| 1시간 안에 어렵다고 예측됨 | 빨강 | 10초마다 짧게 |
| 1시간이 이미 지남 | 빨강 | 2초마다 |

OLED에는 `ETA 12m AI`처럼 남은 시간과 예측 방법(AI/N)을 보여 줘요. 시연 모드에서는 `DEMO15/10m`이 함께 나와요.

**예측 순서**: AI → (계산 못 하면) 뉴턴 냉각 → (냉기실 센서 오류면) 직선 추세. 처음 2분 동안은 기울기를 아직 구하지 못해서 뉴턴으로 계산해요.

**시리얼 (115200)**
- 데이터 줄: `D,분,식품칸,냉기실,뚜껑열림,팬,상태,뉴턴ETA,AI_ETA` (ETA 값은 -1 = 모름, -2 = 못 닿음)
- 설정 줄: `CFG,목표,제한,시연여부` (시작할 때 보냄)
- 명령: `r` 새 딸기(시간 0부터) · `m` 모델 정보 · `d` 기록 출력 · `x` 기록 삭제 · `a` 센서 주소

**빌드 환경**
- 보드 매니저: esp32 (Espressif) → 보드 **ESP32 Dev Module**
- 라이브러리: OneWire, DallasTemperature, ESP32Servo, Adafruit SSD1306, Adafruit GFX Library (의존 라이브러리 함께 설치)
- `Wire`, `LittleFS`는 보드 패키지에 기본으로 들어 있어요.
- `precool_ai`, `precool_ai_demo`, `parts_check`는 arduino-esp32로 컴파일 성공을 확인했어요.

## 5. AI 요약 (자세한 내용은 `docs/AI_기술설명.md`)

- **모델**: 특징 4개 `[b−c, c, (b−b_2분전)/2, (c−c_2분전)/2]`를 표준화(z-score)한 뒤, **릿지 회귀(λ=1)**로 2분 뒤 Δb·Δc를 예측해요. b는 식품칸, c는 냉기실 온도예요. 정규방정식은 가우스 소거(부분 피벗)로 풀어요.
- **목표 도달 시간**: 2분 예측을 반복하는 자기회귀 rollout으로 구해요.
  - 최대 90회(180분)까지 반복해요.
  - Δb̂ > −0.005이면 "못 닿음"(−2)으로 처리해요.
  - 목표를 넘는 구간 안에서는 선형 보간해요.
- **비교 기준**:
  - 뉴턴 냉각: 최근 10분의 ln(b − 냉기평균)을 선형 회귀
  - 직선 추세
- **평가**:
  - 실험 단위로 나눠서 5개 중 1개를 시험용으로 써요.
  - 남은 시간 오차는 MAE로 재요. "못 닿음"으로 잘못 예측하면 180분 벌점을 줘요.
- **학습 숫자 18개** (평균 4, 표준편차 4, 가중치 5×2)가 펌웨어의 "학습 모델 (model.h)" 블록에 들어 있어요. 시뮬레이터 "펌웨어로 보내기" 탭에서 새 model.h를 만들어 이 블록을 바꿔 넣어요.
- **현재 모델은 실측이 아니에요.**
  - 3노드 열 모델 시뮬레이션 60회, 학습 표본 31,020개로 사전 학습했어요.
  - 시뮬레이션 계수는 가정값이에요.
  - 시뮬레이션 기준 시험 오차는 AI 7.4분, 직선 15.1분, 뉴턴 45.1분이에요. 실제 상자 성능이 아니에요.
- **검증한 것**:
  - C와 JS 예측 일치: 무작위 2,000건, 차이 0
  - 펌웨어 보간 일치: 241단계, 불일치 0
  - ESP32 컴파일 성공
- **학습 데이터**: 실측 기록은 아직 없어요. 사용자는 실측값을 줄 수 없다고 했어요.
- **품질 판정은 하지 않아요.** 예측은 참고 표시이고, 출하 판단은 사람이 해요.

## 7. 근거 자료와 방향

- 근거 자료:
  - 캐나다 온타리오 농식품부(OMAFRA): 딸기는 수확 후 1시간 안에 예냉하고 0℃ 가까이 유지
  - Mitchell 외(1996): 25℃에서 냉각을 2·4·6·8시간 늦추면 상품성이 20·37·50·70% 감소
  - 목표 1℃는 과육 목표 온도 34°F를 따른 값이에요.
- 대상: 큰 예냉 설비를 갖추기 어려운 작은 딸기 농가, 직거래·로컬푸드 출하 농가
- 차별점: 팬으로 찬 공기를 돌리는 원리 자체는 새롭지 않아요. 다른 점은 들고 다니는 크기에 **식히기·기록·예측**을 한 박스에 묶은 것이에요.
- 안전·윤리:
  - 품질 판정 없이 참고 표시만 해요.
  - 센서 고장이면 측정 불가로 표시하고 팬을 정지해요.
  - 0℃ 아래로 내려가면 팬을 꺼요.
  - 개인정보는 모으지 않아요.
  - 빛과 소리로 함께 알려서 휴대폰 없이도 확인할 수 있어요.
- SDGs: 목표 12(식량 손실 감소), 목표 2(작은 농가 소득)

## 8. 알려진 불일치 · 남은 일

1. **시뮬레이터 안의 링크가 아직 Netlify를 가리켜요.** `web/simulator/index.html`의 "← 홈페이지" 버튼과 사용 안내의 "소스코드 페이지" 링크예요. 배포본과 같게 두려고 저장소에서도 고치지 않았어요. 고칠 때는 `ai/app_template.html`을 수정하고 `python3 ai/build.py`로 다시 만든 뒤 `busrk-ai-studio`에 다시 배포해요.
2. **시뮬레이터에는 favicon이 없어요.** `assets/favicon/favicon.ico`를 함께 배포하면 돼요.
3. **Netlify 사이트는 옛 내용이에요.** 계정 크레딧 초과(결제 관련)로 배포가 계속 거절됐어요. 해결하려면 사용자가 직접 판단해야 해요.
4. **발표 슬라이드는 일부러 수정하지 않았어요.** 사용자가 "PPT에는 적용하지 말라"고 했어요. 그래서 현재 구현과 다른 곳이 있어요.
   - 부착도 슬라이드: Netlify 주소, 부품 번호 목록에 뽁뽁이 단열층(12번)이 없음
   - 작동 흐름·표시 기준 슬라이드: "학습 모델 개발 중/다음 단계"라고 되어 있음
   - 슬라이드 이미지는 아티팩트 안의 `/_blob/…`을 참조해서, 저장소 사본만으로는 그림이 나오지 않아요.
5. **실측 데이터가 없어요.** 실제 상자로 실험을 반복해 기록(시뮬레이터 "실험 기록" 탭이나 `log.csv`)을 모아야 해요. 그 기록만 골라 다시 학습해야 해요.
6. **실제 보드에서 처음부터 끝까지 돌려 본 기록은 이 저장소에 없어요.**
